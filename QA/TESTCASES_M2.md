# M2 테스트 케이스 — 루팅과 손실

> 기준: `MILESTONES.md` M2 확정 규칙. 빌드: `feature/m2-loot-loss`.
> 임시값: 상자 5Tick · 층당 6~8개 · 기본 가방 6칸 · 연속 대기 5Tick/HP +1.
> 판정 우선순위: `Dead > MIA > Loot`, `Dead > MIA > Rest Heal`.
> 결과: Pass / Fail(BUG-ID) / Blocked(사유) / Observed(현재 동작·규칙 미정) / 미실행

### 빠른 검증 장치

- `F4`: 플레이어 왼쪽 실제 상자, 위 Enemy, 오른쪽 탈출구를 배치한다.
- `F5`: 원정 가방을 6/6으로 채워 가득 찬 상태의 상자·바닥 아이템 경계값을 확인한다.
- `F3`: 타일·벽·Player 검색 셀 오버레이를 표시한다.

## 7. 1차 Play 검증 발견 사항 (2026-11-05)

### 확인된 구현 결함 후보

1. InventoryPanel과 임시 M2BagPanel이 모두 I를 처리해 기존 인벤토리 위에 검은 가방 UI가 중첩된다.
2. 인벤토리를 연 상태에서도 방향키 이동과 마우스 월드 입력이 계속 처리된다. 모달 UI로 확정할 경우 입력 차단 누락 결함이다.
3. 기본 검·방패·갑옷은 지급 로그와 전투 효과가 있으나 아이콘·이름 식별성이 부족해 TC-M2-23을 UI에서 확인할 수 없다.

### 사용자 결정 대기

| 항목 | 현재 동작 | 검토안 |
|---|---|---|
| 줍기·버리기 비용 | 둘 다 0Tick | **결정: 줍기 1Tick, 버리기 1Tick** |
| 전투 중 장비 교체 | 교체 비용 규칙 확인 필요 | **결정: 한 부위 교체 성공 시 2Tick. 재선택·실패는 0Tick** |
| 바닥 아이템 다중 인접 | 먼저 Update된 오브젝트가 획득되어 우선순위가 결정적이지 않음 | **결정: 2개 이상이면 `현재 칸 → 상 → 하 → 좌 → 우` 순서의 주변 아이템 목록. 1개면 즉시 획득. 목록 열기·취소·실패 0Tick, 획득 성공 1Tick** |
| 인벤토리 중 입력 | 이동·공격·월드 클릭 가능 | **결정: 시간 정지가 아닌 입력 레이어 분리. 열기·닫기 0Tick, 열린 동안 월드 행동 차단. 내부 행동 비용은 정상 적용되고 Enemy도 행동. 생존 시 UI 유지, 사망 시 즉시 종료** |
| 휴식 입력 | Space 1Tick 무회복, R 5Tick 후 HP +1 | **결정: `R` 제거. Space 짧게 입력은 1Tick 대기, 길게 입력은 자동 반복. 연속 대기 5Tick마다 HP +1. 최대 HP·Enemy 발견·피격·다른 행동 시 자동 휴식 종료 및 미완료 누적 초기화. 키 해제는 자동 반복만 종료해 수동 연속 대기 누적과 같은 규칙 유지** |
| Enemy 포위·자동이동 | 감지한 모든 Enemy가 발견 즉시 최단 경로 추적·공격하며 자동이동도 계속됨 | **결정: 최초 발견 시 `!`와 함께 경계 행동 1회(1Tick)를 소비하고 다음 차례부터 추적. 추적 종료 후 재발견 시에도 적용. 자동이동은 새 Enemy 발견 즉시 예약 경로를 취소하고 다음 이동 전에 조작권 반환. 이미 추적 중인 동일 Enemy로 반복 정지하지 않음** |
| PC 마우스 조작 | 빈 바닥 좌클릭 시 즉시 자동이동하며 인접 Enemy 공격만 일부 지원 | **결정: 첫 좌클릭은 대상 관찰·선택과 예상 경로 표시만 수행하고 0Tick. 선택된 동일 대상을 다시 좌클릭하면 이동·공격·상호작용 확정. 다른 대상 좌클릭은 선택 변경, 우클릭·Esc는 취소. 키보드 행동은 즉시 실행. Play 결과에 따라 반응성 조정** |
| 인벤토리 UI 통합 | `InventoryPanel`과 임시 `M2BagPanel`이 동시에 표시되고 데이터 표현이 분리됨 | **결정: 기존 `InventoryPanel` 에셋을 단일 화면으로 사용. `LootRuntimeState`와 `PlayerEquipment`를 데이터 원본으로 연결하고 `M2BagPanel`은 런타임 화면에서 제거하거나 디버그 전용으로 전환. 가방과 장비 슬롯을 구분하고 기본 장비의 아이콘·이름을 표시. 신규 에셋 제작은 사용성 검증 후 결정** |

### 1차 검증 결론

- 상자 생성·5Tick 개봉·중복 방지, 6칸 가방, 바닥 드롭·재획득·층 이동 소멸, 결과별 보존·전손, 1,439/1,440 경계값, 최소 피해 1과 M1 회귀는 통과했다.
- Unique 1%는 표본 부족으로 통계 검증하지 않았다. M3 자동 개봉 측정 장치에서 확인한다.
- Stash가 프로세스 재시작 후 초기화되는 현재 동작은 기록된 기술 부채이며 이번 결함으로 집계하지 않는다.
- 확정 전인 비용·입력·AI 규칙은 구현을 변경하지 않고 Product Owner 결정 후 기대 결과를 갱신한다.

### 2~3차 검증 결론 (2026-11-06)

- 인벤토리 통합, 장비 장착·해제·버리기, 주변 아이템 목록, Space 휴식, Enemy 경계, PC 마우스 조작, 자동이동 중단과 M1 회귀를 확인했다.
- BUG-011~017은 사용자 Play 재검증을 통과해 종료했다.
- Enemy를 열린 공간에서 따돌리기 어려운 문제는 M2 결함이 아니라 회피 수단 부족으로 분류하고, 문·시야 차단 지형을 M3 설계 후보로 이관했다.
- M2 기능 구현은 완료됐으며 남은 작업은 미실행 경계·데이터 TC와 Unique 확률 측정이다.
