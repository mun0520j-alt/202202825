## 2. 단계별 작업

### 단계 1 — Tick 단위 (9.x에 반영됨 → 아래 표와 일치하는지 검증만, 빠진 상수만 추가)
| 항목 | 현재 코드 | 변경 |
|---|---|---|
| 이동 | 0.2 tick/칸 (5칸=1tick) | **1 Tick/칸** |
| 공격 | 1 tick | **5 Tick** |
| 1 Tick의 게임 시간 | 5분 | **1분** |
| MIA | 288 tick | **1,440 Tick** (다음 날 06:00) |
| 원정 시작 | departureHour=6 | 던전 1층 진입 순간 **06:00 · 0Tick** |
| 추가 상수(정의만) | – | 자정 1,080Tick · 7층 폐쇄 1,110Tick |
- 비율(공격 = 이동 5칸)은 그대로이므로 밸런스 의미는 동일. `TickCost`, `DungeonClock` 주석·상수 갱신.
- Tick은 정수로 처리 가능하면 int로 (기획서: "이동을 소수점 없이 정수로").

### 단계 2 — 전투 (대부분 9.x에 있음 → 빠진 것만: 적의 플레이어 공격 여부 확인, 자동 이동 중 적 감지 정지, 적 2종 스탯 차등)
- 플레이어·적 HP, 기본 공격(5Tick), 사망 처리.
- 데미지 공식은 기획서에 수치가 없으므로 `공격력 - 방어력, 최소 1` 같은 **임시 공식 + 파라미터화**. 공식 위치를 한 곳(예: `CombatFormula.cs`)에 모을 것.
- 적: 기존 Idle/Wander/추적에 **인접 시 공격** 추가. 적 2종(스탯만 다름).
- 플레이어 자동 이동 중 적 감지 시 정지(현재 스텁) 실제 연결.

### 단계 3 — 층 구조와 탈출
- 1→2→3층, 계단으로 하강만 가능(**이전 층 복귀 불가**).
- 3층에 고정 탈출구. 탈출은 **탈출 절차 Tick**이 든다(값 미확정 → 파라미터, 임시 30Tick). 판정은 **절차 완료 시점** 기준.
- 원정 결과 3종: **생환 / 사망 / MIA(1,440Tick 초과)**. 결과 화면에 경과 Tick, 도달 층, 획득 아이템 표시.
- 결과 후 "다시 출격"으로 0Tick부터 새 원정(영지는 버튼 하나짜리 임시 화면이면 충분, 영지에서는 Tick 안 흐름).

### 단계 4 — 상자 루팅
- 층마다 일반 상자(잠금 없음). 열기 = Interact Tick(임시 3Tick, 파라미터).
- 아이템 등급 Normal/Rare/Epic (1~4층 상한 Epic). 등급 확률은 미확정 → 파라미터.
- 기존 `EquipmentItemDefinition`/`InventoryPanel`에 연결. **사망·MIA 시 전부 손실, 생환 시 보존.**

### 단계 5 — 테스트를 위한 장치 (중요: 사용자가 QA 포트폴리오로 씀)
- **시드 고정 맵 생성:** 인스펙터/디버그 메뉴에서 시드 입력 → 같은 시드면 같은 맵·적·상자 배치. 버그 재현용.
- **Tick 로그:** 행동마다 `[Tick 누적] 행동 / 비용 / 액터` 를 콘솔 + 파일(`Logs/tick_log.txt`)로 기록.
- **디버그 명령:** 현재 Tick 설정, 다음 층 계단으로 이동, HP 설정, 결과 강제(생환/사망/MIA). Development 빌드에서만 활성.
- **HUD:** 현재 시각(HH:MM), 누적 Tick, 층, HP. 3층 탈출구 위치는 상시 표시(기획서 "탈출구 정보 상시 공개").
