# 버전·태그 규칙

> 사용자 결정 2026-11-11. M5부터 적용한다. M4까지의 태그(`v0.0-base` ~ `v0.4-m4`)는 이미 원격에 있으므로 이름을 바꾸지 않고 그대로 둔다.

## 1. 트랙 두 개

| 구분 | 표기 | 태그 | 대상 | 올라가는 시점 |
|---|---|---|---|---|
| 개발 마일스톤 | **M`X`** (X = 자연수) | `mX` (예: `m5`, `m6`) | 내부 개발 | 마일스톤 범위·필수 TC 완료 후 main 병합 시 |
| 배포 빌드 | **BETA 0.`X`** (X = 자연수) | `beta-0.X` (예: `beta-0.1`, `beta-0.2`) | itch 업로드 | itch에 올릴 때마다 |

- 두 번호는 서로 독립이다. M6 진행 중 패치만 해서 BETA 0.2·0.3을 올릴 수 있고, M7까지 끝낸 뒤 BETA 0.2를 올릴 수도 있다.
- 0.9 다음은 0.10이다. 정식 출시는 1.0.
- 긴급 패치가 필요하면 `beta-0.X.Y`를 쓸 수 있으나, 기본은 다음 0.X로 올린다.

## 2. 흐름

1. 마일스톤 브랜치(`feature/...`)에서 개발 → PR → main 병합 → 병합 커밋에 `mX` 주석 태그.
2. 배포가 필요하면 main에서 공개 빌드 정리(디버그 비활성 등) → 빌드 → 빌드로 BETA 체크리스트 확인.
3. 통과한 커밋에 `beta-0.X` 주석 태그 → itch 업로드.
4. `CHANGELOG.md`와 itch 페이지에 같은 버전 이름으로 패치 노트.

## 3. 지킬 것

- **한 번 쓴 BETA 번호는 다시 쓰지 않는다.** 같은 번호로 재업로드 금지.
- **게임 화면에 버전을 표시한다** (타이틀 또는 화면 구석 `BETA 0.X`). 피드백 스크린샷에서 버전을 확인하기 위함.
- **업로드한 빌드 zip은 버전별로 보관한다** (`Builds/beta-0.X/` 등, 리포에는 올리지 않음).
- **itch 업로드 버전 칸에도 같은 이름을 넣는다.** butler 사용 시 `--userversion beta-0.X`.
- 태그는 주석 태그(`git tag -a`)만 사용한다. push·태그 생성은 사용자 확인 후.
- 공개 빌드 파일명은 `dungeon-extraction-beta-0.X-windows.zip` 형식을 사용한다.
- 세이브 스키마를 올리기 전, 마이그레이션 회귀용 이전 버전 샘플을 `QA/evidence/saves/<배포 버전>/`에 보관한다. 샘플 파일은 사용자가 준비하며 민감한 로컬 정보는 포함하지 않는다.

## 4. 이력

| 태그 | 트랙 | 내용 |
|---|---|---|
| `v0.0-base` ~ `v0.4-m4` | 개발 (구 표기) | M0~M4 |
| `m5` | 개발 | 세이브·영지 기초·상인·가방·Esc 메뉴 |
| `m6` | 개발 | 격자 인벤토리 |
| `m7` | 개발 | 메타 경제 — 잡템·구매·탈출 스크롤·보험·세이브 v4 |
| `beta-0.1` | 배포 | 첫 itch 공개 Windows 빌드 — `m7`과 같은 merge 커밋 `56aec4b` |

`m7`과 `beta-0.1`처럼 개발 마일스톤 완료 커밋이 그대로 공개 빌드 기준이면 같은 커밋에 두 주석 태그를 붙일 수 있다.
