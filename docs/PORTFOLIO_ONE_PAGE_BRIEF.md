# Extraction Dungeon Crawler — 기획·QA 프로젝트 브리프

## 한 줄 소개

Tick 기반 턴제 던전에서 전리품을 획득하고, 사망·MIA의 손실 위험을 감수하며 탈출하는 1인 개발 프로젝트다.

## 담당 역할

- 제품 목표·규칙·우선순위 결정
- 테스트 설계, 경계값·결정 테이블 작성
- 직접 Play 검증과 결함 재현
- Jira·Git·Confluence 추적 체계 운영
- 반복 구현과 자동화에 AI 도구 활용, 결과는 직접 검토·승인

## 핵심 문제와 해결

| 문제 | 접근 | 결과 |
|---|---|---|
| 탈출·사망·MIA 동시 발생 | 상태 전이·결정 테이블·1,439/1,440/1,441 경계값 | Dead > MIA > Escaped 확정 |
| 루팅·가방·손실 조합 복잡성 | 결과×아이템 출처 표, 6/6 경계, 전투 중 UI 검증 | BUG-011~019 발견·종료 |
| 생성 맵·확률을 수동 검증하기 어려움 | Seed 1,000개×3층, 층별 100,000회 자동화 | 재현 가능한 M3 측정 기반 구축 |
| 문서와 실제 상태 불일치 | Git 원본·커밋 해시·Confluence 동기화 규칙 | M1 미실행 표시 오류 발견·교정 |

## 현재 결과

## 다음 검증

Unity Editor 자동화 실행과 플레이 5판을 통해 3층 탈출 목표 300~450Tick의 적절성을 판단한다. 수치 변경은 측정 근거와 사용자 결정 이후 진행한다.

## 보여주는 역량

기능을 많이 만드는 것보다 제품 의도를 검증 가능한 규칙으로 바꾸고, 발견한 문제를 문서·티켓·회귀 테스트로 끝까지 닫는 과정에 집중했다.
