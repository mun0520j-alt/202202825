# M6 격자 인벤토리 결정 회의

- 일자: 2026-11-11
- 상태: 기획 확정 / M6 구현 대기 (미결 1건: 상자 재개봉 Tick)
- 결정자: 사용자 (Product Owner)
- 관련: Jira DUN-56(에픽 → 범위 변경 필요), `MILESTONES.md`, `docs/VERSIONING.md`

## 1. 논의 배경

M6 메타(보험·탈출 스크롤·상인 구매·우호도) 범위를 정리하던 중, 익스트랙션 장르의 핵심인 **격자 인벤토리**가 빠져 있음을 확인했다.
현재 가방은 "아이템 1개 = 1칸" 목록이라, 무엇을 들고 나갈지 공간으로 고민하는 경험이 없다.

- 사용자 판단: "정말 익스트랙션 장르라면 격자식이 아니면 이 장르를 채택 안 했다."
- 리포 기획 문서에는 아이템 크기 규칙이 없었다. 이번 회의에서 신규로 확정한다.
- 비교한 안: ① 1아이템=1칸 유지 / ② 칸 수 가중치(목록 UI 유지) / ③ 타르코프식 2D 격자 → **③ 채택**
- 메타 시스템(보험·스크롤 등)도 결국 격자 안의 아이템이므로, 기반인 격자를 먼저 만든다.

## 3. 확정 결정

### 3-1. 격자와 아이템

| 항목 | 결정 |
|---|---|
| 격자 적용 범위 | **출격 가방만.** Stash는 무한 목록 유지 (M8까지 보류 — "지금 할 때가 아니다") |
| 아이템 모양 | **직사각형만** |
| 아이템 크기 (임시값) | 무기 1×3 / 방패 2×2 / 갑옷 2×3 / 가방 2×2 / 스크롤 1×1 (M7) |
| 회전 | **R키, 90도, 0Tick** |
| 줍기 | 빈 자리에 **자동 배치**. 자리가 없으면 줍기 실패 + **"공간 부족"** 표시, Tick 소모 없음 |
| 격자 안 이동(드래그) | **0Tick** |
| 줍기·버리기 | 1Tick (기존 유지) |

아이템 크기는 CSV 값으로 둔다(코드 하드코딩 금지). 임시값이며 Play 후 조정한다.

### 3-2. 가방 격자

| 가방 | 기존 칸 수 | 격자 | 칸 수 |
|---|---:|---|---:|
| 없음 (기본) | 6 | 3×2 | 6 |
| Normal | 8 | 4×2 | 8 |
| Rare | 9 | 3×3 | 9 |
| Epic | 10 | **5×3** | **15** |
| Unique | 12 | **4×5** | **20** |

- 기본 3×2에는 갑옷(2×3)을 회전하면 정확히 들어간다(가방이 꽉 참).
- Rare(3×3)는 Normal(4×2)보다 1칸 많지만 **모양이 달라 쓰임이 다르다**: 3×3은 갑옷+무기 동시 수납 가능, 4×2는 갑옷 회전 후 1×2만 남아 무기 불가. 칸 수가 아니라 모양으로 가방을 고르게 된다.

### 3-3. 가방 교체 — 단계적 (① → ③)

| 단계 | 규칙 |
|---|---|
| **M6 (①)** | **던전 안 가방 교체·해제 불가.** 들고 들어간 가방이 그 원정의 보관함. 던전에서 주운 가방은 2×2 **빈 아이템**(그 안에 넣을 수 없음, 가방 안 가방 아님) |
| M6 (영지) | 가방 교체 가능. **이전 가방의 내용물은 자동으로 Stash로 이동** (Stash 무한이라 실패 없음) |
| M8 (③) | 타르코프식: 내용물이 든 가방을 바닥에 내려놓기·줍기, 가방째 Stash 보관 |

- 비교 후 제외: ② 교체 시 새 가방에 자동 재배치 — 배치 결과를 예측하기 어렵고 중간 단계로 애매함.
- 이유: ③은 중첩 보관함이 필요해 Stash 격자와 같은 기능이다. 자원·구현 한계를 인정하고 단계적으로 간다.
- 플레이 의미: 좋은 가방을 주워도 이번 판엔 못 쓴다 → "살아서 나가면 다음 판부터 큰 가방"이 생환 동기가 된다.
- **M5 결정 대체:** "원정 중 가방 장착·교체·해제 2Tick"(M5 가방·Esc 메뉴 확정)은 폐기. TC-M5-76·76A·76B·76C는 M6에서 폐기 처리.

### 3-4. 던전 장비 해제

- 던전에서 장비를 해제할 때 가방 격자에 자리가 없으면 **실패 + 이유 표시, Tick 소모 없음.** (기존 2Tick 교체·해제 규칙은 성공 시에만 적용)

### 3-5. 루팅 UI — 상자·보스·바닥

| 대상 | 결정 |
|---|---|
| 상자 | **모든 상자 5×5 격자.** 담긴 아이템 종류와 무관. 열면 상자 격자가 뜨고 꺼내 간다 |
| 상자 열기 | 5Tick (기존 유지) |
| 상자에서 꺼내기 | **아이템 1개당 1Tick** |
| 상자 재개봉 | **미결** — 0Tick 또는 1Tick (6장) |
| 보스 드롭 | **보스가 죽은 칸에 5×5 루팅 보관함 1개.** 꺼낼 때 1Tick, **유예(시간 정지) 없음** |
| 바닥 아이템 | 버린 것·넘친 것도 **같은 격자 루팅 UI로 표시.** 아이템이 몇 칸인지 보여야 판단할 수 있다. 기존 주변 아이템 목록을 대체 |

- 보스 유예 없음 이유: 처치 후 5층에 적이 없고 루팅 비용은 최대 2Tick. M4의 "Tick 페이백·시간 정지 제외" 원칙 유지.
- **M4 결정 일부 변경:** 보스 드롭은 바닥 개별 아이템 → 5×5 루팅 보관함 1개. 드롭 수량·등급 확률(0/1/2개 10/70/20%, Rare/Epic/Unique 50/40/10%)은 그대로.

### 3-6. UI 배치

- 화면 맨 아래 배치를 쓰지 않는다. 가독성 우선.
- **왼쪽 = 바깥(상자·보스·바닥 루팅), 오른쪽 = 내 것(인벤토리).** 영지(왼쪽 상인 / 오른쪽 장비·가방·Stash)와 같은 규칙으로 게임 전체를 통일한다.
- 인벤토리: 오른쪽 패널, **위 장비 슬롯 / 아래 가방 격자.**
- 격자 한 칸 **48px 이상.** 아이템 이름은 **마우스 오버 툴팁** (BUG-035 같은 글자 겹침을 구조적으로 방지).
- 영지 출격 가방도 같은 격자 컴포넌트를 재사용한다.

### 3-7. 세이브 v3

- 출격 가방 아이템마다 `x`, `y`, `rotated` 저장. `save_version` 3.
- v2 세이브 로드 시 자동 배치, 들어가지 않는 아이템은 Stash로 이동하고 로그.

### 3-8. Tick 예산

- **1,440 유지.** 2,880 확대 검토 → 기각.
- 근거: M4 5층 생환 평균 723Tick(예산의 약 50%). M6 추가 비용 예상은 한 판 +10~20Tick (상자당 꺼내기 약 +1, 보스 최대 +2, 격자 정리·회전 0).
- 2,880이면 1~5층에서 예산의 약 25%만 사용 → MIA 압박 소실. 1,440은 1Tick=1분 기준 **하루(24시간)**로, 자정·심야·7층 00:30 폐쇄 설계가 이 시계 위에 있다.
- **재검토 조건:** M6 이후 Random 측정에서 5층 생환 평균이 850Tick(목표 상한)을 넘으면 Tick 예산 또는 행동 비용을 재검토한다.

## 5. QA 초점 (TC 후보)

- 배치 경계: 격자 가장자리, 회전 후 경계 초과, 꽉 찬 상태 줍기 → 공간 부족·0Tick
- 회전: R키 0Tick, 회전 상태 세이브·로드 유지
- 기본 3×2 + 갑옷 회전 수납(정확히 꽉 참)
- 가방별 모양 차이 (Rare 3×3 갑옷+무기 가능, Normal 4×2 불가)
- 던전 가방 교체·해제 시도 → 불가·이유 표시
- 영지 가방 교체 → 내용물 Stash 이동, 손실·복제 없음
- 상자 5Tick 개봉 + 꺼내기 1Tick/개, 재개봉 Tick
- 보스 루팅 보관함: 위치, 1Tick/개, 동시 판정(보스 사망·광역 예약 취소) 회귀
- 바닥 아이템 격자 표시, 크기 확인
- 장비 해제 공간 부족 → 실패·0Tick
- 세이브 v2 → v3 마이그레이션, 들어가지 않는 아이템 Stash 이동
- Tick 회귀 측정: 5층 생환 평균 (기준 850)
- M1~M5 핵심 회귀: 결과 판정·손실·Tick 비용
