# M1·M2 기획·QA 사례

## M1 — 원정 결과 판정

### 문제

탈출·사망·MIA가 같은 Tick에 겹칠 수 있어 단순 정상 경로 확인만으로는 결과의 신뢰성을 보장할 수 없었다.

### 접근

- 1,439·1,440·1,441 Tick 경계값 분석
- Dead, MIA, Escaped 결정 테이블 작성
- 탈출 10Tick 동안 Enemy 행동을 포함한 상태 전이 검증
- 자동 경로가 MIA 이후 계속되는 회귀 확인

### 결과

Dead > MIA > Escaped 우선순위를 확정하고 BUG-003·006~010을 수정·회귀 검증했다. M1 수동 TC는 완료됐으며 맵 생성 3건은 M3 자동화로 이관했다.

## M2 — 루팅과 손실

### 문제

가방 초과, 바닥 드롭, 장비 교체, 생환 보존, 사망·MIA 전손이 함께 작동해 조합 오류 위험이 컸다.

### 접근

- 결과 × 아이템 출처의 보존 결정 테이블
- 6/6 가방, 중복 상호작용, 1,435Tick 개봉의 경계값
- 장비 교체 2Tick 동안 Enemy 행동과 사망 처리
- 주변 상호작용 목록으로 입력 충돌 제거

### 결과

BUG-011~019를 발견·종료했고 M2 TC 59/66 Pass를 확보했다. 통계·데이터 기반 항목은 DUN-39·40으로 이관해 M3 자동화 범위를 정의했다.

## 보여주는 역량

- 기획 의도를 검증 가능한 규칙과 경계값으로 변환
- 결함을 재현 절차·우선순위·회귀 결과로 관리
- 수동 검증의 한계를 자동화 요구사항으로 전환
- Jira, 리포 문서, Confluence를 같은 근거로 연결
