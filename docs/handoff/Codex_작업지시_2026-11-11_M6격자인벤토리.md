## 0. 진행 방식 — 단계별 체크포인트

작업량이 크다. **각 단계 끝에 커밋하고 짧게 보고**한 뒤 다음 단계로 간다. 사용자가 단계 사이에 Play 확인할 수 있다.

| 단계 | 내용 | 보고 후 사용자 확인 |
|---|---|---|
| 1 | 격자 데이터 모델·CSV·자동 검증 | 코드 리뷰만 (Play 불필요) |
| 2 | 던전 인벤토리 격자 UI | Play: 배치·회전·드래그·툴팁 |
| 3 | 루팅 격자 UI (상자·보스·바닥) | Play: 상자 5Tick·꺼내기 1Tick·보스 |
| 4 | 가방·장비 규칙, 영지 연결 | Play: 던전 교체 불가·영지 교체 |
| 5 | 세이브 v3·마이그레이션 | Play: v2 세이브 로드 |
| 6 | TC·문서·통합 검증 체크리스트 | 사용자 통합 Play·회귀 |

**1단계 시작 전에** 아래 "구조 확인"을 먼저 보고하고 사용자 승인 후 코드를 쓴다.

### 구조 확인 (코드 작성 전 보고)

## 1. 사용자 결정 (2026-11-11) — 원문 기준

### 1-1. 격자·아이템

| 항목 | 결정 |
|---|---|
| 격자 적용 | **출격 가방만.** Stash는 무한 목록 유지 (M8까지 보류) |
| 모양 | 직사각형만 |
| 크기 (임시, CSV) | 무기 1×3 / 방패 2×2 / 갑옷 2×3 / 가방 2×2 |
| 회전 | **R키, 90도, 0Tick** |
| 줍기 | 빈 자리 **자동 배치**. 자리 없으면 실패 + **"공간 부족"**, Tick 소모 없음 |
| 격자 안 드래그 이동 | 0Tick |
| 줍기·버리기 | 1Tick (기존 유지) |

크기 표기는 `가로×세로`. 무기 1×3 = 가로 1칸, 세로 3칸.

### 1-2. 가방 격자

| 가방 | 격자 (가로×세로) |
|---|---|
| 없음 (기본) | 3×2 |
| Normal (`bag_basic`) | 4×2 |
| Rare (`bag_rare`) | 3×3 |
| Epic (`bag_epic`) | 5×3 |
| Unique (`bag_unique`) | 4×5 |

기본 3×2는 설정값, 가방 4종은 CSV 값으로 둔다.

### 1-3. 가방 교체 (단계 ①)

- **던전 안 가방 장착·교체·해제 불가.** 시도 시 이유 표시("원정 중에는 가방을 바꿀 수 없습니다"), Tick 0.
- 던전에서 주운 가방은 2×2 **빈 아이템**. 그 안에 아이템을 넣을 수 없다.
- **영지 가방 교체 가능.** 이전 가방에 들어 있던 아이템은 **자동으로 Stash로 이동**(Stash 무한, 실패 없음).
- 영지 가방 해제도 같다: 내용물 Stash 이동, 기본 3×2로.
- M5의 "원정 중 가방 교체·해제 2Tick"은 폐기. TC-M5-76·76A·76B·76C는 폐기로 표시.

### 1-4. 던전 장비

- 장비 해제: 가방 격자에 **자동 배치 가능할 때만 성공**(2Tick). 자리 없으면 실패 + "공간 부족", **0Tick**.
- 가방 격자의 장비를 장착(교체): 새 장비가 빠진 자리를 포함해 기존 장비를 자동 배치. 실패하면 **전체 취소**, 0Tick. 성공 시 2Tick (기존 규칙).

### 1-5. 루팅 UI

| 대상 | 결정 |
|---|---|
| 상자 | **모든 상자 5×5 격자**, 담긴 아이템과 무관. 내용물은 상자 안에 남고 꺼내 간다 |
| 상자 열기 | 처음 5Tick (기존) |
| 꺼내기 | **아이템 1개당 1Tick** (가방으로 드래그 또는 클릭) |
| 상자 재개봉 | **미결 — 설정값 `ChestReopenTickCost`, 기본 0.** 사용자가 Play 후 0/1 확정 |
| 보스 드롭 | **보스가 죽은 칸에 5×5 루팅 보관함 1개.** 꺼낼 때 1Tick, 유예(시간 정지) 없음. 드롭 수량·등급 확률은 기존 그대로 |
| 바닥 아이템 | 버린 것·기존 바닥 아이템도 **같은 격자 루팅 UI**로 표시 (몇 칸인지 보여야 함). 기존 주변 아이템 목록 대체 |
| 상자 가득 참 | 가방 초과 시 바닥에 떨어지던 규칙은 사라진다. 아이템은 상자에 남는다 |

- 꺼낼 때 가방에 자리가 없으면 실패 + "공간 부족", 0Tick.
- 가방 → 상자·바닥으로 넣기 = **버리기 1Tick**.
- 바닥 더미: **셀당 5×5 보관함 1개**로 묶는다. 더미가 가득 차면 버리기 실패 + 이유 표시, 0Tick. *(사용자 결정에 없는 경계라 이 규칙으로 구현하고 보고에 "결정 필요"로 올린다.)*
- 층 이동 시 바닥 더미·상자 내용물 소멸 (기존 규칙).
- 동시 인접(문·상자·바닥 더미)은 기존 `DungeonInteractionMenu` 선택 흐름 유지.

### 1-6. UI 배치

- 화면 맨 아래 배치 금지.
- **왼쪽 = 바깥(상자·보스·바닥 루팅), 오른쪽 = 내 것(인벤토리).** 영지(왼쪽 상인 / 오른쪽 내 것)와 같은 규칙.
- 인벤토리 패널: 오른쪽. **위 장비 슬롯 / 아래 가방 격자.**
- 격자 셀 **48px 이상**, 해상도 변경 시 잘리지 않게.
- 아이템 이름·등급·수치는 **마우스 오버 툴팁.** 셀 안에는 아이콘(없으면 등급색 사각형)과 짧은 표기만.
- 루팅 UI를 열면 인벤토리 패널이 같이 열린다. Esc는 루팅 UI → 인벤토리 순으로 하나씩 닫는다 (M5 Esc 우선순위 유지).
- 드래그 중 R 회전 가능. 놓을 수 없는 위치는 빨간 미리보기.
- **영지 출격 가방도 같은 격자 컴포넌트를 재사용**한다. `BaseCampManagementPanel`(OnGUI)에 격자를 OnGUI로 다시 만들지 않는다. 방식은 구조 확인 때 제안.

### 1-7. 세이브 v3

- 출격 가방 아이템: `item_id`, `instance_id`, `x`, `y`, `rotated`. `save_version` 3.
- v2 로드: 가방 아이템을 자동 배치, 들어가지 않는 아이템은 Stash로 이동하고 로그.
- 상자·바닥 더미 내용물은 저장하지 않는다 (원정 중 종료 = MIA 규칙 유지).

### 1-8. Tick

- MIA 1,440 유지. 이번 작업으로 Tick 상수를 바꾸지 않는다.
- 6단계에서 Random 3판 이상 5층 측정. **5층 생환 평균이 850Tick을 넘으면 보고**(사용자가 재검토).
