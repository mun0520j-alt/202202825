## 1. UX 추가 — Esc UI 우선순위와 일시정지

| 항목 | 규칙 |
|---|---|
| 동작 | 인벤토리가 열려 있을 때 `Esc`를 누르면 인벤토리를 닫는다 |
| 비용 | 0Tick (기존 열기·닫기와 동일) |
| 입력 우선순위 | 인벤토리가 열려 있으면 `Esc`는 **인벤토리 닫기만** 처리한다. 같은 입력으로 월드 선택 취소·경로 취소·다른 UI 동작이 함께 일어나지 않는다 |
| 중첩 UI | 주변 아이템 목록·주변 상호작용 목록·문/상자 선택 UI가 열려 있으면 **가장 위의 UI 하나만** 닫는다. 한 번의 `Esc`로 여러 UI가 동시에 닫히지 않는다 |
| 일시정지 | 다른 UI가 없을 때 `Esc`는 계속·설정·종료 메뉴를 연다. 전체화면·해상도를 세이브에 유지한다 |
| 종료 | 영지는 저장 후 종료, 원정 중은 MIA·전손 경고 확인 후 종료 |

수정 전 확인:
- `Esc` 입력을 처리하는 곳을 `rg "KeyCode.Escape"`로 모두 찾고, 같은 프레임 중복 처리 여부를 확인한다.
- 인벤토리 열림 상태의 데이터 소유자(`InventoryPanel.IsOpen` 등)를 기준으로 판단한다.

TC (`QA/TESTCASES_M4.md` 또는 릴리스 TC 문서):

| ID | 절차 | 기대 결과 |
|---|---|---|
| TC-R-01 | 인벤토리를 열고 `Esc` | 인벤토리 닫힘, 0Tick, 다른 동작 없음 |
| TC-R-02 | 월드에서 대상 선택 후 인벤토리를 열고 `Esc` | 인벤토리만 닫히고 월드 선택은 유지 |
| TC-R-03 | 다른 UI가 없는 상태에서 `Esc` | 계속·설정·종료 메뉴 표시 |
| TC-R-04 | 주변 아이템 목록이 열린 상태에서 `Esc` | 목록만 닫힘 |
| TC-R-05 | 인벤토리 열고 `Esc` 연타 | 첫 입력은 인벤토리만 닫고 다음 입력은 일시정지 메뉴, Tick 소비·중복 행동 없음 |

## 2. 공개 빌드 정리

| 항목 | 내용 | 확인 방법 |
|---|---|---|
| 디버그 키 | F3·F4·F5·F6 및 QA 메뉴 비활성화 | 공개 빌드에서 키 입력 시 반응 없음 |
| 측정 기록 | M3 측정 CSV·Seed 요약이 생성되지 않음 | 공개 빌드 실행 후 `persistentDataPath`에 `M3Measurements` 미생성 |
| Seed | 항상 Random | 출격 로그 또는 연속 출격 시 맵 상이 |
| Unity MCP 패키지 | 빌드에 포함되지 않음 (BUG-002 Won't Fix 항목) | 빌드 로그·출력 폴더 확인 |
| 개발용 로그 | 과도한 `Debug.Log`가 플레이에 영향을 주지 않음 | 공개 빌드 성능·로그 파일 크기 확인 |
| 빌드 | Windows x64 빌드 생성 | 리포 밖 다른 폴더로 복사 후 실행, 출격→5층 보스→생환 1판 완주 |

`ProjectSettings/PackageManagerSettings.asset`은 커밋하지 않는다. 빌드 설정 변경이 생기면 커밋 전에 보고한다.
